# CLAUDE.md

Notes for working on this repo. The README is the user manual (features, controls, limitations, project layout); read the relevant section before changing a feature, and update it in the same change.

## What this is

"Sandbox" / AUBO ARCS Simulator: a Flask web UI (`backend/webui.py`, page `backend/templates/index.html`) around a Viser 3D viewer (`backend/robot_sim/`) for planning, baking and running paths on AUBO i-series arms over the ARCS RPC SDK (`pyaubo_sdk`, wrapped by `backend/robot_sim/arcscontrol.py`). Target platform is **Windows** (the SDK, Steam Deck Tools, XInput, Edge); Python 3.12 (pyaubo-sdk has no wheels past 3.12).

- `python backend/webui.py`: full sandbox on http://127.0.0.1:5000, Viser on 8080 (iframe).
- `python backend/deck_webui.py`: Steam Deck edition, same backend, `templates/deck.html`. Never run both at once (same ports).
- `python backend/deck_app.py`: Deck edition as a desktop app (preloader + pywebview window); the entry point of ArcsDeck.exe.

## Layout and paths

- Every file the app reads or writes resolves through `backend/app_paths.py`. `ARCS_USER_DIR` / `ARCS_STATE_DIR` relocate `user_files/` and `backend/state/` (the .exe points them into its unpack folder).
- Modules in `backend/robot_sim/` and `backend/cameras/` are imported by bare name (`import waypoints as wp`, `import robot_runtime as rr`); `webui.py` puts those folders on `sys.path`. `webui.py` registers itself as `webui` when run as `__main__`, so `import webui` reuses the running module.
- `robot_runtime.py` finds URDFs under `<its folder>/aubo-i5-full-master/aubo_description/urdf` (`aubo_i*.urdf`, with an optional `<model>_sim.urdf`).
- `user_files/settings.json` holds settings plus the global saved points and paths. `user_files/paths/` and `user_files/exports/` are git-ignored.

## Gimbal objects

- Gimbal joints are J1-J3 (J1 at the handle) in UI, docs and script prints; data keys and the SDK stay yaw / roll / pitch (J1 = SDK joint yaw). Nothing gimbal-specific is in code: shape, joint axes, offsets and the default driver come from a model file (`user_files/gimbal_models/*.json`, `cfg.model`, read and re-read on change by `backend/robot_sim/gimbal_model.py`: product-of-exponentials chain, Look At solve, viser box build). The mount is the handle (link-0 parts); twins are nested joint nodes with their link parts and a camera frame (z lens, x right, y image down, like a viser camera), no camera body. Objects can be parented to `<oid>#sim` (`_obj_parent` resolves it with `gimbal.twin_camera_world`; `_set_twin` / `rebuild` propagate it); a new gimbal gets a Camera object there (`add_gimbal_camera`, local rx 180: Camera objects look along their -z, y up). The Sim gimbal can have a collider (owner `<oid>#sim` in colliders.py, record `obj["gimbal"]["collider"]` {enabled, stop, margin}): its shapes are the model's parts on links >= 1 (`gimbal_model.world_parts`), never the handle, and it is not tested against its own gimbal's mount collider. Recalibrate (`/api/gimbal` action calibrate, `gimbal._calibrate_home` on the gimbal thread, no move, nothing recorded): the gimbal is in its home pose (handle vertical, hand end up, camera at +x, level, no roll = the model's all-zero pose); `gimbal_model.home_offsets(model, reading, mount_wxyz)` sets each joint's offset so the camera at that reading looks along WORLD +x, level (`home_world_q`, through `ik` on a sign-1 / offset-0 copy, nearest the zero pose; unrotated mount -> the reading maps to 0), and the Sim target becomes the reading -> `write_joints` (`.orig` once, `.<date-time>.bak` each time). An earlier version moved the camera to attitude 0 / 0 / 0 first: with the hand end up that turned J1 by 180, so don't. Joint `sign` / `offset` in a model file map SDK readings to model angles (`joint_values`, back with `stored_values`). Test it with a simulated driver that computes `get_world()` from a known model. `dji_rs4.json`: hand end up; all joints 0 = home pose, camera along +x, level (offsets from the home reading J 173.5 / -179.0 / -69.4); J2's axis along the lens [1, 0, 0]; J3 sign -1 (the RS4's J3 reading turns the other way to the model's J3 axis: tilt was inverted with +1); the pan arm and roll motor are behind the lens (-x), the roll arm / tilt motor on the camera's right (-y); its sizes are estimates (no CAD published). (An earlier J2 tilted 56 deg came from fitting with J2 modelled near 180; the home-pose zero replaces it.) World <-> joints: `gimbal_model.world_ypr` / `world_q` (camera yaw, pitch, roll in the world) and `ik` (least squares from the current angles); `/api/gimbal` world_target and the Sim Gimbal Cursor's rotate-only gizmo (`gimbal.show_twin_gizmo`, at `twin_camera_world`, shown by `waypoints._apply_selection_viz` when the `#sim` part is selected) set the target through it. Children of `<oid>#sim` (the Camera) never drive the gimbal: their edits only change their offset. Stored values may go past +/-180 for all three joints (LIMITS +/-20 turns; the SDK move limits are not joint limits; `_move` sends each in +/-180). Real-pose frames: key flag `live` (kept by `clean_keys`); `stored_keys` = as stored, `keys_for` = as played: a live frame takes `rt["live_read"]` (the reading at the tick a real run starts, cleared after it; the frames after it shift by reading - stored live angles, frozen for the run in `rt["run_keys"]`, so each run makes the same turns) or else `_live_sim` (IK for camera along world +x, level, from the Sim mount; cached), unwrapped near the frame before; edits use the stored frames; `go_to_initial_pose` / `at_initial_pose` skip a live first frame; `insert_frame` / `edit_frame` take `live`; webui `_display_tracks()` sends gimbal tracks as played (the page shows those angles; it never edits gimbal frames through /api/tracks). Frame directions: key field `dir` = [J1, J2, J3] of `FRAME_DIRS` ("" as set / short / cw / ccw), kept by `clean_keys`; every frame edit goes through `_set_keys` -> `resolve_keys` (a tagged joint takes the turn `_turn_to` gives from the frame before; an untagged one keeps its step from it); `/api/gimbal` frame_dir {index | t, dir} (`set_frame_dir`); the first frame's dirs are the initial-pose move (`first_dirs`, in `go_to_initial_pose`, "" = short). CW / CCW per joint come from the model joint's `view` (`rising_is_ccw(obj, i)`: dot(axis, -view) * sign > 0; defaults: J1 looking along -z, others against their axis). Moves take per-joint directions (`move_dirs`: list, or one word = J1's); any cw / ccw -> `_jmove_start` (per joint from the reading). `_drive_run` caps each absolute move at `STEP_MAX_DEG` (90) for the joints it drives, so long turns go the frames' way; it turns J1 by speed only when J1 changes in the keys (else all three absolute, J2 included). The SDK absolute move is in camera world angles, not J1-J3: `_move` refuses (cmd_err) while `handle_tilt(obj)` (real mount `_real_root`, hand end vs world up) is over `ATTITUDE_TILT_MAX` (20 deg); with the handle horizontal a J3 absolute pitch swung J1, and attitude roll is limited to +/-30. Then `_joint_mode(obj, rt)` (tilted + driver has track_* and `track_j3`): `_drive_run` turns J1 by speed (`_track_j1`) and J3 by `_track_j3` (driver `track_j3(delta, duration)`: RS 4 incremental pitch in 3D ROLL 360, J3 only per the axis probe; `J3_INCR_SIGN` -1: pitch +x -> J3 reading -x; steps aim `J3_STEP_S` ahead, wait `J3_SETTLE_S` after each), nothing absolute, J2 held; every request goes through `_jmove_start` then. Probe result (handle horizontal): speed-pitch in normal mode and incr-pitch in both modes turn only J3; speed-pitch in 3D ROLL 360 turned J1 -147 too. Status `tilt` / `joint_drive`. `go_to_initial_pose` queues `rt["initial_req"]`, sent by `_tick_one` once `_mount_still(rt)` (`_track_mount`: the real mount unmoved for `MOUNT_STILL_S`; at most `INITIAL_WAIT_S`), and the hold pauses (speed 0) while the mount moves: driving while the arm turned the handle fought the RS 4's stabilising (moving to random poses). (Counting the Sim mount's tilt for joint mode made that worse and was dropped.) `_track_j1`'s runaway guard: error > best + `RUNAWAY_DEG` -> stop, `_track_end`, forget `j1_sign`, drop jmove / hold, cmd_err; `err_min` resets on a new jmove / Repeat. A real run calls `_drive_run(..., follow=False)` and drives one way for the whole run, `rt["run_drive"]` from `_run_drive_kind` at its start ("joint" when the driver can and J2 doesn't change, or the handle is tilted; the tilt changes as the arm moves, and switching mid-run made J1 burst): in joint drive only feed-forward (`_track_j1(follow=False)`: the keys' slope plus (track - `tk["ff"]`) / LA, `ff` = integral of the speeds sent, starting from frame 0; no reading correction / guard; `_track_j3_ff`: steps of the keys' change from frame 0, `rt["j3_ff"]`), nothing (and `_track_end`) when `_keys_move` is false; J1 direction learning only while `_mount_still`. Closed loop fought the RS 4's stabilising during buffer runs (spinning). Start check: `robot_runtime.real_at_start()` = arm on the first sample and `gimbal.at_initial_pose()` (readings within `START_TOL_DEG` of frame 0: J1 / J3, J2 unless joint drive; not-reading gimbals aren't checked); `real_path_status` sends `gimbal_start` (why), shown when Run starts the move phase. `go_to_initial_pose` sets `rt["start_hold"]` (time): after its jmove, `_tick_one` keeps `_drive_run(keys[:1])` going (joint mode only) while `_run_waiting()` (an arm's `_rp` uploaded and not active, or the solo upload), dropped when the run starts or 2 s after nothing waits; the jmove's end skips `_track_end` then. A request with the same goal as the running jmove (`_goal_sig`) is skipped, and `_jmove_start` keeps an existing track (no mode change).
- `backend/robot_sim/gimbal.py`: scene object kind `"gimbal"` = mount empty (`handle`) + Sim and Real twins (`sim_head` / `real_head`, child scene nodes of the mount, so they follow its pose and visibility). The twins are list rows `<oid>#sim` / `<oid>#real` (built in the page, like arm cursors); selecting one selects the gimbal object and sets `gimbal.part_of(oid)` (no gizmo, no delete). The Real twin shows only while `real_ok()`. Reading is always attempted; `cfg.drive` gates moves. `obj["gimbal"]["look"]` is the Sim gimbal's Look At (`aim_angles`, own target resolver `look_target_pos`, safe on the gimbal thread); it overrides the track and, during a run, `_drive_look` streams it. A new gimbal (`add_gimbal_camera` sets `rt["adopt_read"]`) takes the first good reading as its target, unless the target was set (`update`) or it has frames / Look At. Saved data is `obj["gimbal"] = {cfg, target}` (`clean_gimbal`), in file save and undo snapshots; undo snapshots also hold the gimbal tracks' frames (`gimbal_tracks`, put back by `gimbal.restore_track_keys`), and `/api/gimbal` pushes an undo step before each settings / target / frame edit. Snapshots hold numpy arrays: `restore_scene_object` reads vectors through `_vec_or` (`v or default` on an array raised and dropped every object on undo). Frames live on the extra track `gimbal_<oid>` as `{t, yaw, roll, pitch}`; J1 (yaw) is unwrapped on the timeline (LIMITS +/-20 turns: frames 0 -> 360 = a full turn; old `spin` keys convert in `clean_keys`; readings / IK / aim results go through `unwrap_yaw`). Move real to sim takes `direction` per joint (`request_move`, `move_dirs`): any cw / ccw runs a one-off two-key track through `_drive_run` (`rt["jmove"]`, `_jmove_start` / `_jmove_tick`); RS 4: a rising J1 reading is clockwise from the hand end, a rising J3 reading clockwise from the tilt motor (not yet checked on the hardware). Run drive (`_drive_run`, one way for the whole run): J1 by speed (`_track_j1`, driver's optional `track_begin / track_speed / track_end`, unwrapped J1 from readings, command sign learnt once), J3 by absolute moves with yaw and roll None, only when J3 changes (an absolute roll is attitude: it pulled a turning camera back past 180 deg; the same goes for cw / ccw moves); `_track_end` before any other move when the run stops / pauses / waits between plays; `sync_tracks` (called from `sync_camera_tracks`) keeps one per gimbal. `/api/tracks` keeps the server's gimbal keys; frames are edited only through `/api/gimbal` (insert_frame `source: "real"` keys the reading: the timeline row's orange +; the timeline's select / drag / Delete use `move_frames {moves: [{t0, t}]}` and `delete_frame {ts}`; page state `gimSel` / `gimDrag`, `hitGimFrame`; the sidebar's click-to-deselect skips gimbal frames; right-click `#gimMenu` (`showGimMenu`, Edit… / Copy / Cut / Paste / Delete; an empty spot of a gimbal row: Paste there), Ctrl+C / X / V via `gimCopy` / `gimPaste` (page clipboard `gimClip`, `window.__clipKind` picks gimbal or arm paste), the Edit window `#gimEditModal` (`openGimEdit`, also dblclick) -> `edit_frame {index, t?, angles?, dir?}`, paste -> `paste_frames {frames}`, hover hint `gimFrameHint`; Properties has no frame list). Simulate plays to `solo_t_end()` when gimbal frames end after the arm's path (`rr._gimbal_end`: `_pb` / `_rp` `t_end`, the real run's finish and Repeat wait for it); the gimbal clock during a run is `_rp.t - preroll` (path time). `_tick_one` saves the Sim target when a Simulate starts (`_sim_playing`) and puts it back for `RESTORE_HOLD_S` after it ends (the playhead is set back then, which used to set the target from the track there). Gimbal cursor eyes are item_vis `obj:<oid>#sim` / `#real`, applied on the gimbal thread (`_user_shows`). Properties scrubbing: `setupScrub` (delegated pointerdown on a label followed by a number input; change fires on release); `label.drag` fields keep their older handler. Timeline track names (`renderLabels`): a resizable column (`--tl-names-w`, `tlNamesResizer`, localStorage `tlNamesW`) plus a + column (`trackPlus`: arm rows Real / Sim waypoint, gimbal rows Real / Sim frame); only `custom_` tracks get a delete bin.
- Bake speed check: `robot_sim_run._bake` calls `gimbal.speed_check()` (per segment, |delta| / dt against joint `max_dps`, J1 also against `TRACK_MAX_DPS`; segments < 0.1 s); `/api/status` sends `gimbal_speed` (per track) and `gimbal_speed_note` (bake hint); `_note_keys_changed` drops a track's report. `gimbal.tracks_baked()` (every gimbal track with >= 2 frames has a report) gates Simulate of a gimbal-only timeline; `tracks_ok()` (baked, nothing too fast) gates `runnable` / Upload for any timeline (`/api/real/upload` refuses too).
- Real side (`backend/robot_sim/real_mirror.py`, `tick()` every viewer tick from `robot_sim_run`): objects under each arm's sim cursor (any depth, through `<oid>#sim`) are mirrored onto the real cursor (pose = real * inv(sim) * object), or onto the sim cursor while `arms.real_ok[aid]` (cached by `arms.listing()`) is false ("Robot Not Connected", row id `real_none[@aid]`). Gimbals: the Real twin is a top-level node `/gimbal_real_<oid>` placed by `gimbal.place_real_root` (on its own mount when not on an arm); `twin_camera_world(obj, "real")` uses that root. Others: ghost nodes `/real_ghost_*` (built from kind / scale / mesh / gimbal handle, opacity x0.5), off with setting `real_ghosts`. `/api/status` `real_side` gives the rows; the page lists them, and a ghost / stand-in row is selected in the page only (`window.__realSel`, `realSelObject`: read-only Properties, Local / Global switch local to the page). `robot_runtime.reset_sim_to_real` (every snap sim -> real path) also calls `gimbal.snap_to_real()`; a gimbal not reading yet gets `rt["snap_until"]` (`SNAP_WAIT_S`, 30 s) and `_tick_one` snaps it on its first good reading (the robot's connect snap comes before the gimbal reads).
- Gimbal-only playback (no arm has >= 2 waypoints, a gimbal track has >= 2 frames): `gimbal._solo` is its own clock (`solo_sim_start` / `solo_upload` (initial pose) / `solo_real_start` / `solo_pause` / `solo_stop`, looping in `_solo_tick_locked`); `_clock()` returns it while active. webui: `_solo_playable()` makes `runnable` / `sim_runnable` true, `_with_solo` merges `solo_status(kind)` into the sim / real status when no arm plays, `/api/clock` takes its t, and the simulate / pause / upload / start / stop / halt routes fall through to it; status `gimbal_only_real` enables Upload / Run / Stop with the arm offline.
- Adding or deleting a waypoint (`add_waypoint`, `delete_selected`) calls `path_bake.invalidate_from(0)` (not `drop_all`, which only new documents / clear use): every span unbaked, sample times carried by `_carry_from` (old span with the same end times, or the old frames inside a split or merged span, resampled); `seg["kept_times"]` (from a baked or kept span) makes `timeline.py` list those samples while unbaked.
- Joint / IK field edits of the Sim Arm Cursor (`rr.apply_selected_q` / `apply_selected_ik`) place its gizmo with `_place_sim_gizmo` (position and heading): while the gizmo is shown, each controller tick takes the heading from it in local axes, so moving it without turning it turned the cursor back away from its children (`_move_cursor_children` had already placed them), and real_mirror's offset (and the Real Gimbal Cursor) moved.
- Undo / redo of scene objects (`waypoints._restore_objects_snapshot`, full rebuild path) re-places every object whose parent is not a scene object (arm cursors / base, any depth through `_propagate_children`) from its snapshot local pose on the parent's current pose: cursor moves are not undo steps, and restoring world poses pulled children off the cursor (and their copies off the Real Arm Cursor). Each scene-object gizmo drag pushes one undo step (`_bind_object_gizmo`, `_drag_checkpointed`, reset on drag end).
- Export (`/api/file/export` -> `file_manage.write_export_json`, the page downloads the returned `doc`): `gimbals` from `gimbal.export_tracks()` (frames + `poses` every `EXPORT_STEP_S`), and each point's `gimbal` {oid: [J1, J2, J3]} at its time (points carry `dur`, not `t`: times are summed). Speed graph: `renderSpeedGraph` scales to the fastest sample drawn; its Export POSTs {sim, real} to `/api/speed_export` (GET only before: every export failed with a 405), which writes `exports/speed_export.json` (samples, `bake.export_overspeed()`, `gimbal.export_tracks()`) and returns it as `doc` for `downloadJson`.
- Timeline: a sample outside its segment's waypoint times gets status `out` (red, `timeline.py`). A pointerdown on the timeline blurs a focused input / select (the canvas can't take focus: the gimbal frame hotkeys went to the field).
- Autosave (`webui._autosave_loop`): every 60 s and ~2 s after each undo step (`wp.on_edit` hooks in `_push_history`); `write_autosave` skips an unchanged document.
- `rs4_can.py` run drive: `track_begin` starts `_Streamer` (owns the bus until `track_end` / `close`): speed every `STREAM_TICK_S` (50 ms, like `rs4_spin_360.py`), angle requests without waiting (`get_angles` returns its latest, raises if stale), `track_j3` / `move_to` queued; the sandbox's blocking reads between speed commands made J1 burst. `gimbal._log_run` keeps each gimbal's last real run (`rt["run_log"]`, `run_logs()` -> speed export `gimbal_runs`, with the driver's `track_stats()`).
- All gimbal I/O is on the `gimbal` thread (`tick()` at 10 Hz); web requests are queued (`request_move`). The driver is a user script (`user_files/gimbal_scripts/rs4_can.py`, DJI R SDK over python-can) loaded per object. The run is detected from each arm's `_rp` / `_pb` without swapping arms.
- No gimbal or CAN adapter in the cloud container: test with a stub script that implements `connect / get_angles / move_to / close`.

## Viewer clients

- The page opens Viser for the world view and for camera panes with different `initialCameraPosition` URL tags (`robot_runtime.view_tag_query`, passed to index.html as `viser_url` / `viser_cam_url`); a client's role comes from its first camera report (`_client_role`, `_world_ids`), not from connection order. Untagged clients (older viser, the Deck page) fall back to "first client is the world view".

## Steam Deck edition

- `backend/deck_webui.py`: routes under `/api/deck/...`, jog logic, `boot()` (settings, viewer, Steam profile, pad, hold watchdog) and `serve()` (Flask, blocking).
- `backend/deck/pad.py`: Deck controls as an XInput pad. `backend/deck/steam_profile.py`: switches Steam Deck Tools' `SteamController.exe` to the hidden "Arcs Deck" profile and back on exit.
- **Version**: `DECK_VERSION` in `deck_webui.py` and `VERSION` in `deck/pad.py` (also the `# version:` first line of `deck_webui.py`), shown in Settings and printed on start. Bump both together for a Deck feature change; commits are titled `Deck 1.x: ...`. `deck/preloader.png` has the version drawn on it ("v deck.1.8") and must be re-exported by hand when it changes.
- Nothing is autosaved in the Deck edition.

## Game controller in the sandbox

- `backend/gamepad.py` reads one Xbox / PlayStation / other pad through SDL2 (`pygame._sdl2.controller`, `SDL_JOYSTICK_ALLOW_BACKGROUND_EVENTS=1` so it reads while the browser has focus), falling back to XInput (`deck/pad.py`). `identify()` names the family / type from the SDL GUID's USB vendor and product ids. `map_controls()` is the Deck's mapping with L1 / L2 and R1 / R2 for L4 / L5 and R4 / R5; X is the west face button (PlayStation Square).
- `webui.py` calls `deck_webui.start_controller()` on start, so the sandbox uses the Deck's jog engine (`_jog_step`, real jog, Sim / Real target) and settings (`deck_lin_mps`, `deck_rot_dps`, `deck_ramp_s`, `deck_real_jog`). Importing `deck_webui` must stay side-effect free for the sandbox: the Deck page replaces `/` only in `deck_webui.boot()`.
- `/api/controller` (GET status, POST `{target}`) feeds the Controller row in the 3D view's top-right box and Preferences > Controller. pygame is excluded from ArcsDeck.exe (the Deck uses XInput only).
- No controller can be tested in the cloud container: check `identify()` / `map_controls()` directly and the UI with no device.

## ArcsDeck.exe (packaging/deck)

- PyInstaller one-file build: `packaging/deck/ArcsDeck.spec`, deps in `packaging/deck/requirements-build.txt`, Windows script `packaging/deck/build_deck.bat` (venv `.venv-deck-build`, output `dist/ArcsDeck.exe`). CI: `.github/workflows/build-deck.yml` (windows-latest, Python 3.12, on push to `steamdeck/**` or by hand; the exe is the `ArcsDeck` artifact).
- Startup has two splash stages that must line up: PyInstaller's `Splash` (shown while the exe unpacks; one line, the file being unpacked) and then `deck_app.Preloader` (Tk on its own thread, last `LOG_LINES` (3) log lines). The splash is `SPLASH_WIDTH` = 504 px wide (60 % of the earlier 840); the log font is given in pixels (negative Tk size) so it fits the white strip. Both use `deck_app.SPLASH_WIDTH`, `splash_image()` and `splash_text_pos()`; the spec imports `deck_app.py` for them, so keep its top level free of heavy imports. The preloader stays up at least `MIN_SPLASH_S` (4 s) and until the page loads.
- The transparent top of `preloader.png` is made see-through on Windows with a magenta key colour (alpha is thresholded, no soft edges). PyInstaller writes the splash font family into Tcl unquoted, so the spec passes it in braces (`{Segoe UI}`).
- The exe is windowed: stdout/stderr go to the preloader (and to a console with `--console`). The app window is pywebview with `gui="edgechromium"` (WebView2); if that fails it falls back to `deck_webui._open_deck_ui` (Edge/Chrome `--app` or the browser), and the process then runs until ended. Closing the pywebview window restores the Steam profile and exits (`os._exit`).
- Bundled data: `templates/`, `deck/preloader.png`, `user_files/settings.json`, `aubo-i5-full-master/{aubo_description,robotiq_85_gripper}`, plus `collect_data_files` for viser (web client) and collada (schema for .DAE meshes) and `collect_all` for skrobot, trimesh, pyaubo_sdk, webview. `cv2`, `pandas`, `usb`, `pygrabber` are excluded (camera / bake-report features the Deck page lacks); code that lazily imports them must cope with the ImportError.
- Testing the build without Windows: on Linux the spec builds a Linux binary (install `python3.12` + `python3-tk`, the build requirements minus pyaubo-sdk, and put a stub `pyaubo_sdk.py` with an `RpcClient` class on `PYTHONPATH`). Run it under `Xvfb` and screenshot with `PIL.ImageGrab.grab(xdisplay=":99")`. pywebview has no GUI backend there, so it uses the browser fallback; ports 5000 and 8080 should answer.

## Conventions

- Commit titles: short, sentence-style, describing the behaviour change (e.g. `Deck 1.7: real jog accelerates and decelerates (Real ramp time setting)`). British spelling in UI text and docs ("colour", "centre").
- There is no automated test suite; check changes by running the app (or the steps above for the exe).
- Do not commit `user_files/paths/`, `user_files/exports/`, `build/`, `dist/` or `.venv-deck-build/`.
